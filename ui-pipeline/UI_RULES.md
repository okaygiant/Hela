# Правила работы с UI — Hela

Ты собираешь UI для Hela (Telegram Mini App, Next.js 16 + Tailwind v4 + shadcn, код в `hela-app/`).
Результат должен быть предсказуемым: ты не придумываешь визуал, а собираешь его из токенов и паттернов, которые уже есть.
Перед работой с Next.js прочитай `node_modules/next/dist/docs/` (см. `AGENTS.md`): API версии 16 отличаются от привычных.

## 1. Источники правды (по убыванию приоритета)
1. **Figma «DE»** (`cm9ueRUqblIdeipUobd3eI`, секция «App», node `498:2353`, 8 экранов): дизайн.
2. **`hela-app/app/tokens.css`**: значения. Только semantic-токены, примитивы `--p-*` не использовать в компонентах.
3. **`hela-app/app/tokens-tailwind.css`**: имена токенов в Tailwind (таблица в разделе 3).
4. **`ui-pipeline/ui-kit.md`**: паттерны (chip, CTA, карточки, tab bar…) с размерами и токенами.
5. **`ui-pipeline/refs/`**: экспорты экранов без хрома Telegram.

Если нужного токена или паттерна нет, СТОП: спроси, не изобретай. Если источники противоречат друг другу, спроси.

## 2. Жёсткие запреты
- Никаких hex, rgb(), hsl() вне `tokens.css`.
- Никаких произвольных значений в Tailwind: `p-[13px]`, `text-[17px]`, `bg-[#111]`, `rounded-[15px]`. Дробные шаги шкалы кроме `0.5/1.5/2.5` тоже нельзя (`p-3.5` нельзя).
- Никаких новых цветов, теней, шрифтов, градиентов «для красоты».
- Не менять `tokens.css`, `tokens-tailwind.css` и существующие компоненты без явной просьбы.
- Не переписывать экран целиком, если просили поправить деталь.
- Никаких внешних UI-библиотек и CDN без разрешения.
- Не использовать модификатор прозрачности на токен-цветах (`bg-surface-app/50`): не работает. Нужна прозрачность, значит нужен новый токен, спроси.

## 4. Процедура «Figma → код»
Для каждого значения из макета:
1. **Точное совпадение** с токеном: используй токен.
2. **Отклонение ≤ 1–2 px** от токена: округли до токена и перечисли это в отчёте («в макете 13, взял `text-13`/`p-3`»).
3. **Совпадения нет**: СТОП, спроси, не подбирай на глаз и не делай произвольное значение.

Размеры рамки макета (390 × 984/854, верхний отступ 130) не копировать: см. раздел 7.

## 5. Порядок работы
1. **Структура.** Сначала текстом: иерархия экрана, паттерны из `ui-kit.md`, данные. Жди аппрува.
2. **Раскладка.** Серый вариант на токенах, без декора.
3. **Стилизация.** Только токены. Акцент один на экран.
4. **Самопроверка** (раздел 6). Результат приложи.
5. **Правки** маленькими диффами, перечисляй что поменял.

## 6. Состояния
**По умолчанию** у каждой кнопки и ссылки (`<button>`, `<Link>`, кликабельная плитка) стоит `PRESS` из `components/press.ts`: pressed (сжатие + затемнение), focus-visible, плавность 200 мс. У основной CTA бери `CtaButton` / `CtaLink` (там есть ещё disabled и loading). Не спрашивай про это каждый раз и не пропускай при вёрстке нового экрана.

В макетах нарисованы только default-состояния. Остальные (pressed, disabled, loading, empty, error) не придумывай: перечисли, какие нужны, и спроси. Для денежных значений проверь: ноль, очень длинное число, отказ транзакции, потерю сети (покажи, как это выглядело бы, и спроси, если дизайна нет).

## 7. Telegram Mini App (WebView)
- Шапку «mini app», статус-бар, скругление рамки и Home Indicator рисует Telegram, их не строим (`ui-kit.md`, раздел 1).
- Ширина гибкая, высота `min-h-app`, верх и низ `pt-safe-top` и `pb-safe-bottom`. Не `100vh`, не `w-[390px]`, не `h-[844px]`.
- SDK подключён (`components/telegram-provider.tsx`, `lib/telegram.ts`).
- Не использовать цвета и шрифты хрома Telegram и ThemeParams: палитра Hela фиксирована.
- Только касания: ничего не должно зависеть от hover. Тап-зона ≥ 44 px (у маленьких кнопок: `relative after:absolute after:-inset-2`).
- Иконки из `public/helabet/` обрезай по контуру перед использованием (`public/helabet/icons/*.webp` уже обрезаны): в исходных PNG большие прозрачные поля.
- Скримы (`bg-scrim-bottom`) с размытием делай плавными: `backdrop-blur-glass-md mask-t-from-40%`, иначе виден жёсткий край блюра.

## 8. Самопроверка перед сдачей
1. `node ui-pipeline/lint-tokens.mjs <изменённые .tsx/.css файлы>`: 0 нарушений. Линтер ловит hex/rgb, px, произвольные значения (`p-[13px]`), дробные шаги (`p-3.5`), стандартную палитру Tailwind (`bg-red-500`, `text-white`), `h-screen`/`100vh`. Исключение в одной строке: комментарий `lint-ignore: <причина>`. Числа в `style={{ padding: 13 }}` линтер не видит, их смотри глазами.
2. Скриншоты на 360, 390, 430 px; нет горизонтального скролла, ничего не обрезано.
3. Сравнение со скриншотом Figma: список расхождений.
4. Пройти `ui-pipeline/checklist.md`: ок / не ок / нет данных. «Ок» без проверки не писать.
5. Не сдавать с известными нарушениями.
